## 一、数据库迁移脚本（汇总）

### 1.1 P0-1 机会窗口追踪

```sql
-- 画像机会窗口表
CREATE TABLE IF NOT EXISTS profile_opportunities (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  child_id UUID NOT NULL REFERENCES children(id) ON DELETE CASCADE,
  
  dimension VARCHAR(50),
  element VARCHAR(50),
  description TEXT NOT NULL,
  suggestion TEXT,
  
  status VARCHAR(20) DEFAULT 'open',
  first_appeared_at TIMESTAMP,
  last_appeared_at TIMESTAMP,
  appearance_count INT DEFAULT 1,
  warning_level INT DEFAULT 0,
  
  source_record_id UUID,
  resolved_record_id UUID,
  
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_opportunities_child ON profile_opportunities(child_id);
CREATE INDEX IF NOT EXISTS idx_opportunities_status ON profile_opportunities(status);
CREATE INDEX IF NOT EXISTS idx_opportunities_warning ON profile_opportunities(warning_level);
```

### 1.2 P1-3 家长反思记录

```sql
-- 家长反思表
CREATE TABLE IF NOT EXISTS parent_reflections (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  child_id UUID REFERENCES children(id) ON DELETE SET NULL,
  
  content TEXT NOT NULL,
  related_record_id UUID,
  related_opportunity_id UUID,
  
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_reflections_user ON parent_reflections(user_id);
CREATE INDEX IF NOT EXISTS idx_reflections_child ON parent_reflections(child_id);
```

### 1.3 P2-1 预警系统

```sql
-- 预警通知表
CREATE TABLE IF NOT EXISTS opportunity_notifications (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  child_id UUID NOT NULL REFERENCES children(id) ON DELETE CASCADE,
  opportunity_id UUID NOT NULL REFERENCES profile_opportunities(id) ON DELETE CASCADE,
  
  level INT NOT NULL,
  title VARCHAR(50),
  message TEXT,

```

## 二、技术债务清单

### 2.1 高优先级（影响稳定性和安全）

| 序号 | 问题 | 影响 | 解决方案 |
|------|------|------|----------|
| 1 | **TypeScript 7.0.2 (Beta)** | 可能包含未知 bug，生产环境风险 | 升级到稳定版（如 5.x）或使用 LTS 版本 |
| 2 | **middleware 文件废弃** | Next.js 新版本已废弃 middleware | 改用 proxy 方案（参考 CLAUDE.md 已有说明） |
| 3 | **standalone 构建 static 目录问题** | 历史教训，需手动软链接 | 写入部署脚本自动处理 |
| 4 | **API 错误返回格式不统一** | 有的返回 `{error}`，有的 `{code, message}` | 统一为 `{code, message, data}` 格式 |

### 2.2 中优先级（影响可维护性）

| 序号 | 问题 | 影响 | 解决方案 |
|------|------|------|----------|
| 5 | **WebSocket 文件存在但未使用** | 代码冗余，不知道是否保留 | 明确是废弃还是未来功能，清理无用代码 |
| 6 | **缺少单元测试** | 重构风险高，不敢改代码 | 逐步补充核心模块测试 |
| 7 | **DeepSeek API 无重试机制** | 网络波动时直接失败 | 增加 3 次重试 + 指数退避 |
| 8 | **数据库连接池未配置** | 高并发可能出问题 | 添加 `max_connections` 配置 |

### 2.3 低优先级（代码质量）

| 序号 | 问题 | 影响 | 解决方案 |
|------|------|------|----------|
| 9 | **前端状态分散** | 画像数据在多处管理 | 统一到 ChildContext |
| 10 | **硬编码字符串** | 国际化困难 | 提取到 constants |
| 11 | **注释缺失** | 新人上手困难 | 补充关键函数注释 |

## 三、测试计划

### 3.1 单元测试（优先级：高）

**测试框架**：Jest + React Testing Library

**覆盖模块**：

| 模块 | 测试用例 |
|------|----------|
| `src/lib/db.ts` | query / queryOne 基础查询 |
| `src/lib/auth-utils.ts` | getAuthFromRequest 鉴权 |
| `src/lib/profile-extractor.ts` | extractEventsFromRecord / analyzeProfile |
| `src/lib/api.ts` | 各 API 方法（mock fetch） |

**示例**：
```typescript
// src/lib/__tests__/db.test.ts
describe('db', () => {
  it('query returns array', async () => {
    const result = await query('SELECT 1 as value');
    expect(result).toEqual([{ value: 1 }]);
  });
});
```

### 3.2 集成测试（优先级：中）

**测试场景**：

| 场景 | 测试内容 |
|------|----------|
| 登录流程 | 注册 → 登录 → 获取 token → 访问受保护接口 |
| 陪伴记录流程 | 提交记录 → AI 分析 → 保存 → 查看报告 |
| 滋养时刻流程 | 添加时刻 → 提取 → 生成报告 |

**工具**：Playwright（端到端测试）

### 3.3 AI Prompt 测试（优先级：高）

**测试方法**：
1. 准备测试用例集（标准输入 + 期望输出结构）
2. 批量调用 API，验证返回 JSON 结构
3. 人工评估回复质量

## 四、开发优先级顺序

### 4.1 推荐实施路径

```
第一阶段：核心闭环（P0）
├── P0-1：机会窗口追踪闭环     [优先级：最高]
└── P0-2：滋养时刻主动引导     [优先级：高]

第二阶段：体验增强（P1）
├── P1-1：六要素雷达图        [优先级：中]
├── P1-2：压力吐槽 Prompt 升级 [优先级：高]
└── P1-3：家长反思记录        [优先级：中]

第三阶段：产品深化（P2）
├── P2-1：预警系统           [优先级：低]
└── P2-2：分享海报增强        [优先级：低]

贯穿始终：技术债务
├── API 错误格式统一
├── DeepSeek 重试机制
└── TypeScript 版本升级
```

### 4.2 各阶段工作量估算

| 阶段 | 模块 | 预估工作量 |
|------|------|-----------|
| P0 | P0-1 机会窗口追踪 | 中（需新增表 + 改造 API + 前端） |
| P0 | P0-2 滋养引导 | 小（主要前端交互改造） |
| P1 | P1-1 雷达图 | 大（评分算法 + 图表组件） |
| P1 | P1-2 Prompt 升级 | 小（只改 prompt） |
| P1 | P1-3 反思记录 | 中（新增表 + API + 前端） |
| P2 | P2-1 预警系统 | 中（依赖 P0-1） |
| P2 | P2-2 海报增强 | 小（主要是 UI 改造） |

### 4.3 技术债务处理建议

| 债务 | 建议处理时机 | 风险 |
|------|-------------|------|
| TypeScript 升级 | P0 之前或 P2 之后 | 中 |
| middleware→proxy | 发现问题时处理 | 高 |
| API 格式统一 | 每个功能改造时顺便改 | 低 |
| 重试机制 | 单独一个 PR，统一处理 | 低 |
| 测试覆盖 | 贯穿始终，逐步补充 | 低 |
