# 望杏成林 wxcl-v2 项目评估与改进框架

> 评估时间：2026-07-29
> 评估人：灵机

---

## 一、项目概述

**项目名称**：望杏成林（wxcl-v2）
**项目定位**：面向家长的"内在结构养育"育儿支持系统
**技术栈**：Next.js 16 + React 19 + TypeScript 7 + PostgreSQL + DeepSeek API
**访问地址**：https://wxcl.nzyy.cc/v2

### 核心功能模块

| 模块 | 功能描述 |
|------|----------|
| 🌿 陪伴&观察 | 记录日常与 AI 分析，亮点+机会窗口 |
| 💬 压力吐槽 | 家长倾诉 + AI 专业回应 |
| 💧 滋养时刻 | 记录被孩子滋养的时刻 + 周期性报告 |
| 👤 孩子画像 | 性格/兴趣/优势/成长目标 |
| 📊 全景报告 | 周报/月报 + 周对比 + 行动建议 |

---

## 二、内在结构养育体系理解

这是一个专业育儿理论框架，核心理念是**"从行为到结构"**——不只看孩子的行为，而是看行为背后的内在心理结构。

### 核心框架

| 维度 | 内容 |
|------|------|
| **六要素** | 心神、自我意向、本能情感愿望、内化客体、妥协与防御机制、内在准则与价值意义 |
| **五大心理营养** | 自主、实事求是、自我负责、建设性、同情心 |
| **四大推力原则** | 分离个体化、与现实相洽、撑起内在空间、双向沟通通道 |
| **五个成全层面** | 永葆热情→识风险知进退→激发勇气→实现价值→享受其中 |

### 核心理念落地情况

- ✅ 不直接说"孩子有问题"，而是通过"机会窗口"引导
- ✅ 两套认知体系（家长显性 vs AI隐性）数据库设计完整
- ✅ 动态权重机制（家长认知与AI分析的差异处理）
- ⚠️ **滋养时刻设计优秀**但引导机制缺失
- ❌ AI分析结果未反向作用于陪伴回复质量

## 三、综合评估

### ✅ 做得好

| 方面 | 说明 |
|------|------|
| **理念落地** | 陪伴记录、压力吐槽都用上了内在结构养育的 prompt 框架 |
| **滋养时刻** | 产品设计优秀：事实+感受，主动从记录中提取，周期性报告 |
| **画像体系** | 六要素视角的事件库、版本历史、动态权重设计完整 |
| **全景报告** | 周对比、行动建议、里程碑都有，report 生成质量高 |
| **Onboarding** | 回忆采集→初始画像，用户旅程清晰 |
| **架构清晰** | Next.js App Router，API 路由模块化，数据库层封装良好 |
| **代码质量** | TypeScript 类型完善，React 19 + 新语法，组件职责单一 |

### ⚠️ 不足与问题

| 问题 | 说明 |
|------|------|
| **两套认知体系前端缺失** | 数据库设计了，但家长看不到"AI的分析"和"我的认知"的差异 |
| **滋养引导断点** | 设计了提取功能，但用户不知道"可以提取"，缺少主动引导 |
| **机会窗口未闭环** | 报告里的"机会窗口"没有在后续记录中被追踪和回应 |
| **AI回复质量不稳定** | 简单 chat route 和专业的 analyze route 输出差异大 |
| **缺少"结构"可视化** | 用户无法直观看到孩子在六要素上的状态变化 |
| **家长成长路径模糊** | 缺少"家长自己"的反思和成长记录 |

### 🔴 风险项

| 风险 | 说明 |
|------|------|
| **AI 依赖风险** | 核心功能完全依赖 DeepSeek API，API 不可用时功能瘫痪 |
| **standalone 构建问题** | 历史教训（adm.nzyy.cc），static 目录需手动软链接 |
| **HTTPS 代理架构** | 全程 HTTPS 链路长（港服→乌服 443），出问题排查难度大 |
| **TypeScript 7.0.2** | Beta 版本，可能有未知问题 |
| **中间件废弃** | Next.js 新版本已废弃 middleware，CLAUDE.md 提到要用 proxy 替代 |
| **无重试机制** | DeepSeek API 调用失败没有重试逻辑 |
| **错误处理不统一** | 有的返回 `{error}`，有的返回 `{code, message}` |

### 具体改进计划

#### 🔴 P0（核心闭环，必须做）

**1. 机会窗口追踪闭环**

```
当前问题：机会窗口只出现在报告中，之后就消失了

改进方案：
- 每条新记录提交时，自动关联上一次的机会窗口
- AI分析时先读取历史"未解决的机会窗口"
- 回复中体现："上周我们关注了XXX，这周有新的进展吗？"

技术方案：
1. 新增 profile_opportunities 表，记录未解决的机会窗口
2. analyze API 调用前先查询未关闭的机会窗口
3. prompt 中加入"历史机会窗口"上下文
4. 连续3次报告都提到同一方向时，标记为"持续关注"
```

**2. 滋养时刻主动引导**

```
当前问题：设计了提取功能但用户不知道用

改进方案：
- 当滋养时刻 < 3 条时，在陪伴记录提交后主动提示
- "这个记录里有温暖的时刻，要保存到滋养时刻吗？"
- 滋养报告生成时提示可以一键提取

技术方案：
1. 陪伴记录提交成功后，调用提取 API
2. 前端展示提取结果，让用户确认保存
3. 在滋养页面增加"从记录提取"快捷入口
```

**3. 两套认知体系可视化**

```
当前问题：数据库设计了但用户看不到

改进方案：
- 画像页面显示"系统洞察"vs"我的理解"两个版本
- 用不同颜色/透明度区分
- 家长修改后系统保持隐性分析

技术方案：
1. profileApi 增加获取双版本的方法
2. 前端画像页面分区展示
3. 家长编辑后记录 modifiedBy = 'parent'
4. AI分析时降低被修改字段的权重
```

#### 🟡 P1（体验增强，应该做）

**4. 六要素结构雷达图**

```
新增功能：
- 基于事件库，生成孩子在六要素上的状态雷达图
- 支持周对比，看变化趋势
- 每个要素点开看到具体事件

技术方案：
1. profile-extractor.ts 增加六要素评分逻辑
2. 前端使用 Chart.js 或 Recharts 绘制雷达图
3. 综合报告页面增加雷达图展示
```

**5. AI回复质量标准化**

```
当前问题：chat route 和 analyze route 输出质量差很多

改进方案：
- 统一使用 analyze 的专业框架
- 根据场景(daily/venting/question)选择对应 prompt
- 增加回复后的"追问"功能

技术方案：
1. 废弃简单的 chat route，统一走 analyze 逻辑
2. 根据 intent 选择不同的 prompt 模板
3. 前端支持追问按钮
```

**6. 家长反思记录**

```
新增功能：
- "今日家长反思"入口（可选）
- 不是给建议，是家长自己的觉察
- 影响画像中"家长认知"的权重

技术方案：
1. 新增 parent_reflections 表
2. 在陪伴记录页面增加折叠的反思区
3. 滋养报告可以引用家长的反思内容
```

#### 🟢 P2（产品深化，可以做）

**7. 预警系统**

```
新增功能：
- 当某个机会窗口连续3次报告都出现
- 自动标记为"需要关注"
- 推送温和提醒："这个方向最近出现多次，要不要深入聊聊？"

技术方案：
1. 在生成综合报告时统计机会窗口出现频次
2. 连续出现3次标记 warning_level
3. 前端展示警告标识，点击可进入深度分析
```

**8. 分享海报增强**

```
当前：静态图片

改进：支持生成"滋养海报""成长里程碑"等不同类型

技术方案：
1. 使用 html2canvas 生成多种海报模板
2. 海报模板：全景报告版、滋养时刻版、里程碑版
```

**9. 简化版 chat 入口**

```
当前：只有陪伴记录和压力吐槽两个入口

改进：底部新增"聊聊"入口，AI 根据内容自动分类

技术方案：
1. 新增 /api/chat/intent-classify 端点
2. 根据用户输入自动分类为 daily/venting/question
3. 统一走专业框架处理
```

## 五、技术改进建议

| 方面 | 问题 | 改进方案 |
|------|------|----------|
| **错误处理** | API 返回格式不统一 | 统一为 `{code, message, data}` |
| **AI调用** | 无重试机制 | 增加3次重试+指数退避 |
| **数据库** | 连接池未配置 | 添加 `max_connections` 配置 |
| **前端状态** | 画像数据分散 | 统一到 ChildContext |
| **构建** | standalone 需手动软链 | 写入部署脚本自动处理 |
| **WebSocket** | 文件存在但未使用 | 明确是废弃还是未来功能 |
